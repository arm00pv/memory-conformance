## What each mutation is

- **`leak-everywhere`** — Every write is also written outside the store directory and every read returns both, so two separate stores are one store. This is memory-mcp-1file's defect.
- **`no-persist`** — A write is acknowledged and never stored. Everything downstream reads a store that was never written, so the failure propagates by construction.
- **`keep-last`** — Each write replaces the store with itself, so one write survives and three do not. The root probes come apart here: ack_readback still passes it.
- **`no-forget`** — memory_forget answers ok and writes nothing. The record is still readable after the restart, which is the exact failure the caller cannot see.
- **`forget-all`** — memory_forget deletes every record instead of the one named. From the caller's side the answer is identical to a clean delete, so only a probe that also checks what nobody asked to remove can tell them apart.
- **`reshape-modelled`** — Records this server would have written are re-serialised from its own model, so a field another tool attached is discarded on the next write - while records it would never have written pass through untouched. The reference implementation's real defect.
- **`drop-unnamed`** — Anything that is not a record this server would have written is discarded on the next write, and modelled fields on its own records are kept. The mirror of reshape-modelled.
- **`stale-cache`** — The store is read once at startup and rewritten from that copy forever. One process is indistinguishable from correct; two processes each lose the other's writes.
- **`truncate-large`** — Anything longer than 1000 characters is cut to 1000 and acknowledged as stored. A silent cap, which is the failure the ladder in the probe exists to see.
- **`mute-search`** — The store is perfect and nothing is ever found. Retention without retrieval.
- **`blind-search`** — The same three records come back whatever is asked - memento's real defect, which every other probe in the suite would have scored as a pass.

7 of 9 fail **alone** - one mutation reached that probe and stopped there: `isolation`, `forget`, `findable`, `foreign_field`, `foreign_record`, `concurrent`, `large_record`.

The remaining 2 cannot be isolated, and the reason is structural rather than a weakness
in the probes: `ack_readback`, `restart`. Every probe begins by writing a record and
reading it back, so a subject that loses writes at the root fails all of them. The
cascade in those rows is the diagnosis, not an accident of the table.

`forget-all` is the one mutation that no probe returns PASS for and none returns FAIL for either:
a store that deleted everything answers a clean delete exactly as convincingly as a
store that deleted one record, so the probe declines to certify either way. Declining is
the correct answer, and it is why the probe counts the records nobody named.

Every predicted verdict matched, on every mutant, for all 9 probes.
