# Does the retrieval score have teeth

Generated by `retrieval_mutants.py`. Do not edit by hand.

The conformance probes have been mutation-tested since Addendum 19: twelve broken copies of the
positive control, one promise broken each, with a verdict written down before every run. This is
the same treatment for the number the retrieval table publishes, and it asks a narrower question
than whether the corpus is any good. It asks which defects move the score and which it cannot see.

| lever | what it does | hits | hit@1 | score | spoke on unanswerable |
|---|---|---|---|---|---|
| `reverse-rank` | worst match first, the same set of records | **25** | 15 (predicted 0) | **37** | **0** |
| `one-result` | the same search cut down to a single answer | **25** | **25** | **37** | **0** |
| `greedy-match` | one shared term is enough to be an answer | 36 | 32 | 43 | 5 (predicted 12) |
| `strict-match` | every term of the question is required | 15 | 15 | 27 | **0** |

Bold is a prediction written before the run that the run confirmed. A number in brackets beside
its prediction is a miss, left in rather than corrected. Repeated 3 times per question, with the
per-question outcome taken as the majority. Corpus A as written; corpus B is in the table below.

## What it cannot see

**The score cannot see the order of the answers it counts.** A search that puts the worst of
its matches first, returning exactly the same set of records, moves hit@1 from 25 to **15**,
moves hit@3 by 0, and moves the score by 0. Every conclusion in the retrieval table is drawn
from the score.

That is not a bug in the corpus. hit@3 is a set membership question and it answers it. It is a
property of the instrument that had never been written down: a memory server that puts the right
record third and one that puts it first score identically here, and an agent that reads only the
first result is not being measured by this table at all.

It is also where a prediction of mine failed. I predicted hit@1 would fall to zero, because this
control already puts every correct answer first - the matrix prints 25 and 25. It fell to 15, and
the reason is the questions with exactly one matching record: reversing a list of one changes
nothing, so those answers keep their first place. The miss is more informative than the hit would
have been, because it says 15 of the control's 25 correct answers come from a search that had no
ranking to get wrong.

## What it rewards

**A careless matcher outscores a careful one.** Lowering the bar to one shared word raises hits
from 25 to **36** and the score from 37 to **43**, while giving back only 5 of the twelve
unanswerable points. Raising the bar to every word does the opposite: hits 15 and score 27,
ten points below where the same subject started.

So the score is close to monotone in how eagerly a subject answers. The only thing pushing back is
the twelve questions with no answer, and a subject that answers every question it can find a word
for does not even trip all twelve. A memory that retrieves badly and never stays quiet ranks above
a memory that retrieves well and says so when it does not know, and that is the ordering this
table has been publishing.

My prediction here missed in the same direction: I expected all twelve unanswerable questions
answered and eleven or twelve points given back. It was 5, because one shared word between a
question and a record is less common than I assumed - which is exactly why the defect pays.

## What it does see

- `one-result`: cutting the list to one answer moves hits from 25 to 25 and the
  score from 37 to 37 on corpus A - nothing at all, because this control already ranks its answers
  first. On corpus B the same lever moves hits from 32 to 29, where three correct answers were
  found in second or third place. So the corpus can see this defect, on the corpus that has one.

## What this does not say

It does not say the score is the wrong metric. A set membership question is the right question for
a memory that is asked to surface candidates, and hit@3 is the honest name for what it measures. It
says the table has been read as if it measured the quality of a ranking, which it cannot, and that
the matrix already prints hit@1 beside hit@3 - this is the first measurement of whether the choice
between those two columns ever changes a conclusion, and on six of fifty-five pairs it does.

Nor does the mutation battery say the corpus is a bad one. It says which defects it detects and
which it does not, with a number attached to each, which is the same thing the probe battery says
about the probes and for the same reason: an instrument that has never been shown to fail is an
instrument nobody should quote.
