price on a near-tie - 371 questions for the leader against the control, 679 against zenbrain, 11,825
on corpus B - and none of those prices has ever been paid. This pays one of them at a fifth of the
size.

**The store is identical to the sixty-question authorless corpus**: the same 72 real records, already
ingested by every subject. Only the question count changes - each record asked verbatim, with a third
of its words gone, and with half of them gone, plus a drawn absent band.

## What the exam actually asks

**276 questions, every one of them distinct** - and it took a defect to get there. Two packages can
share a description word for word (a fork and its original, a client and a server generated from one
template), so a corpus that derives one question per description asks the same words twice with a
different expected record, and a subject that returns the other one of the two is graded wrong for
being right. The first version of this exam did exactly that, in 12 slots:

- `Model Context implementation for TypeScript - package`
- `Model Protocol for TypeScript - package`
- `State-of-the-art Learning for the web. Run 🤗 directly in browser, no need `
- `State-of-the-art Machine Learning for the web. Run 🤗 Transformers directly`
- `State-of-the-art Machine for the web. Run 🤗 Transformers directly in brows`

Those slots are dropped at build time now - `questions.py` holds the rule, and the
validator, the ledger and the corpus guard all check it - which is why the table above is over
276 questions instead of three hundred. The rows measured against the dropped questions are
excluded from every count rather than re-run: a question two records answer equally was not
measuring the subject, so there is nothing in those rows to rescue.


## What this does not settle

**Three questions about one record are not three independent draws.** The store stayed at 72
records because a larger one was tried first and abandoned: at 282 records the control alone needed
about nine minutes for three hundred questions, because it reads the whole store on every search.
The price of
that choice is correlation, and the direction of the bias matters - correlated questions make
separation harder, so a tie broken here is real evidence and a tie that survives here is weaker
evidence than 276 questions suggests.

Nor does it settle the price for the other near-ties: band.py quotes 1,401 and 11,825 questions for
pairs on other corpora, and those are still unpayable.
